# Хранение данных в локальном SQLite

## Контекст и постановка задачи

История расчётов и тарифы должны сохраняться между запусками приложения. Серверная СУБД недопустима по REQ-SEC-001 и REQ-AVAIL-001. Нужно выбрать локальный формат хранения, который обеспечит целостность данных при сбое.

## Драйверы решения

* Локальность хранения — REQ-SEC-001.
* Целостность при аварийном закрытии — REQ-REL-001.
* Простота резервного копирования.
* Минимум зависимостей для portable-поставки.

## Рассмотренные варианты

* SQLite-файл
* JSON-файлы
* QSettings

## Итог решения

Выбранный вариант: «SQLite-файл», потому что он поддерживает транзакции, SQL-запросы и хранит все данные в одном файле, который легко скопировать. JSON и QSettings не обеспечивают атомарность и подходят только для небольших настроек.

### Последствия

* Хорошо, потому что транзакции защищают историю от частичной записи.
* Хорошо, потому что файл БД можно скопировать как резервную копию.
* Плохо, потому что в сборку нужно включить плагин `QSQLITE`.
* Плохо, потому что при повреждении файла требуется отдельная процедура восстановления.

### Подтверждение

* Тест: аварийное завершение во время записи не повреждает БД.
* Проверка наличия плагина `QSQLITE` в portable-архиве.

## Плюсы и минусы вариантов

### SQLite-файл

* Хорошо, потому что транзакции и SQL.
* Хорошо, потому что один файл для резервного копирования.
* Плохо, потому что нужен плагин `QSQLITE`.

### JSON-файлы

* Хорошо, потому что просто читать вручную.
* Плохо, потому что нет транзакций.
* Плохо, потому что при сбое легко получить частично записанный файл.

### QSettings

* Хорошо, потому что встроен в Qt.
* Плохо, потому что предназначен для настроек, а не для истории расчётов.
* Плохо, потому что нет удобных запросов и транзакций.

## Дополнительная информация

Связанные требования: REQ-SEC-001, REQ-REL-001, REQ-FUNC-004.  
Связанные решения: ADR-0001, ADR-0003.
