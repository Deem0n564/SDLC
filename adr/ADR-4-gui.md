# GUI на Qt Widgets

## Контекст и постановка задачи

Нужно выбрать подход к построению десктопного интерфейса: Qt Widgets, QML/Qt Quick или нативные WinAPI-элементы. Интерфейс «UtilitySmart» состоит из форм, таблицы истории и нескольких окон, без сложной анимации.

## Драйверы решения

* Скорость разработки простых форм и таблиц.
* Стабильность на Windows и Linux.
* Простота сборки и поставки.
* Соответствие REQ-INT-001 и REQ-INT-002.

## Рассмотренные варианты

* Qt Widgets
* QML/Qt Quick
* Нативные WinAPI-элементы

## Итог решения

Выбранный вариант: «Qt Widgets», потому что он проще для форм, таблиц и не требует дополнительного runtime QML. QML избыточен для данного интерфейса. WinAPI привязал бы приложение к Windows.

### Последствия

* Хорошо, потому что интерфейс быстро собирается из стандартных виджетов.
* Хорошо, потому что поведение одинаково на Windows и Linux.
* Плохо, потому что внешний вид менее гибкий, чем в QML.
* Плохо, потому что для сложных анимаций пришлось бы добавлять QML.

### Подтверждение

* Демонстрация главного окна и окна тарифов.
* Проверка отображения на разрешении 1280×720 по REQ-INT-003.

## Плюсы и минусы вариантов

### Qt Widgets

* Хорошо, потому что быстро для форм и таблиц.
* Хорошо, потому что не требует QML runtime.
* Плохо, потому что меньше возможностей для анимации.

### QML/Qt Quick

* Хорошо, потому что гибкий современный интерфейс.
* Плохо, потому что избыточен для простых форм.
* Плохо, потому что усложняет сборку.

### Нативные WinAPI-элементы

* Хорошо, потому что максимально нативно для Windows.
* Плохо, потому что привязывает к одной ОС.
* Плохо, потому что сложнее сопровождать.

## Дополнительная информация

Связанные требования: REQ-INT-001, REQ-INT-002, REQ-INT-003.  
Связанные решения: ADR-0001.
