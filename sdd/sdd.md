## 1. Введение {#1-introduction}

### 1.1 Назначение документа {#11-document-purpose}

Документ фиксирует архитектуру и проектные решения приложения «UtilitySmart», которое предназначено для расчёта коммунальных платежей. SDD отвечает на вопрос, **как** устроена система, чтобы выполнить требования SRS 0.1. Документ адресован разработчику, тестировщику и Заказчику: первый использует его для реализации, второй — для проверки покрытия требований, третий — для контроля сроков и объёма работ.

### 1.2 Область применения {#12-subject-scope}

Описание охватывает десктопное приложение под Windows/Linux: графический интерфейс на Qt 6 Widgets, локальную базу данных SQLite, расчётный модуль, модуль экспорта в CSV и сборку через CMake. Вне области: онлайн-оплата, интеграция с сайтами ЖКХ, облачная синхронизация и мобильные клиенты.

### 1.3 Определения, акронимы и сокращения {#13-definitions-acronyms-and-abbreviations}

## 2. Обзор дизайна {#2-design-overview}

### 2.1 Задачи стейкхолдеров {#21-stakeholder-concerns}

| Стейкхолдер | Задача | Где решается |
|-------------|--------|--------------|
| Заказчик | Уложиться в 12 недель, не потерять данные | DES-004, DES-008 |
| Пользователь | Быстрый расчёт, понятный ввод, защита от ошибок | DES-003, DES-005, DES-006 |
| Разработчик | Понятная структура кода и сборки | DES-002, DES-007 |
| Тестировщик | Проверяемые границы модулей | DES-001, DES-004 |

### 2.2 Выбранные точки зрения {#22-selected-viewpoints}

#### 2.2.1 Контекст {#221-context}

Пользователь работает с локальным десктопным приложением. Внешних сетевых систем нет. Данные хранятся в файле SQLite рядом с исполняемым файлом. Экспорт формирует CSV-файл на диске.

#### 2.2.2 Композиция {#222-composition}

Приложение делится на модули:
- **UI** — главное окно, окно тарифов, окно истории;
- **Calculation** — расчёт суммы;
- **Tariff** — хранение и изменение тарифов;
- **History** — чтение и запись истории расчётов;
- **Export** — выгрузка в CSV;
- **Persistence** — работа с SQLite;
- **Common** — логирование, обработка ошибок, конфигурация.

#### 2.2.3 Логическое представление {#223-logical}

Каждый модуль разделён на слой представления (Qt-виджеты), слой логики (классы-сервисы) и слой доступа к данным (репозитории). Контроллер связывает виджеты и сервисы. Прямое обращение виджетов к SQL-запросам запрещено (REQ-MAINT-001).

#### 2.2.4 Физическое представление {#224-physical}

Portable-версия: каталог с `UtilitySmart.exe`, DLL Qt и файлом `utilitysmart.db`. Установка не требуется. Поддерживаются Windows 10+ и Linux (AppImage/архив).

#### 2.2.5 Структура {#225-structure}

Ключевые сущности: `Tariff`, `Reading`, `Calculation`, `UserSettings`. Связи: расчёт ссылается на показания и тариф; история хранит снимок тарифа на момент расчёта.

#### 2.2.6 Зависимости {#226-dependency}

`Calculation` зависит от `Tariff` и `Reading`. `History` зависит от `Persistence`. `Export` зависит от `History`. Циклических зависимостей нет.

#### 2.2.7 Информация {#227-information}

Модель данных — в приложении А. Денежные суммы хранятся в целых копейках (`INTEGER`), чтобы исключить ошибки округления. Тарифы хранятся в копейках за единицу ресурса.

#### 2.2.8 Интерфейс {#228-interface}

Внутренний интерфейс между слоями — C++-классы с сигналами и слотами Qt. Внешний интерфейс для пользователя — графические окна. Формат CSV — UTF-8 с разделителем `;`.

#### 2.2.9 Взаимодействие {#229-interaction}

Сценарий расчёта: пользователь вводит показания → контроллер проверяет данные → сервис расчёта получает предыдущие показания и тариф → вычисляет сумму → сохраняет запись в историю → обновляет UI. При ошибке выводится сообщение, запись не сохраняется.

#### 2.2.10 Алгоритм {#2210-algorithm}

Сумма = (текущее показание − предыдущее показание) × тариф. Результат округляется до двух знаков (копейки). Если текущее показание меньше предыдущего, расчёт блокируется. Подробно — DES-005.

#### 2.2.11 Динамика состояний {#2211-state-dynamics}

Состояния расчёта: `EMPTY` → `INPUT` → `CALCULATED` → `SAVED`. Переход в `SAVED` возможен только после успешной записи в БД. При ошибке БД состояние остаётся `CALCULATED`, пользователь может повторить сохранение.

#### 2.2.12 Параллелизм {#2212-concurrency}

Приложение однопоточное для UI. Операции с SQLite выполняются в главном потоке; транзакции короткие, что укладывается в REQ-PERF-001. Фоновые потоки не используются.

#### 2.2.13 Паттерны {#2213-patterns}

MVC, Repository, Singleton для подключения к SQLite (в рамках процесса), DTO для передачи данных между слоями.

#### 2.2.14 Развёртывание {#2214-deployment}

Portable-архив. CMake собирает исполняемый файл и копирует необходимые DLL. База создаётся автоматически при первом запуске.

#### 2.2.15 Ресурсы {#2215-resources}

Приложение потребляет менее 100 МБ ОЗУ. Размер БД растёт медленно (несколько записей в месяц). Для сборки достаточно 2 ГБ ОЗУ.

## 3. Проектные представления {#3-design-views}

- **ID**: DES-001-контекст
- **Title**: Контекст и границы приложения
- **Viewpoint**: Контекст (2.2.1)
- **Representation**: Пользователь → GUI → локальная БД SQLite → файл CSV. Внешних сетевых вызовов нет.
- **More Information**: REQ-SEC-001, REQ-AVAIL-001. Решение ADR-0002.

- **ID**: DES-002-композиция
- **Title**: Модульная структура приложения
- **Viewpoint**: Композиция (2.2.2), Логическое (2.2.3)
- **Representation**: Пакеты `ui`, `calculation`, `tariff`, `history`, `export`, `persistence`, `common`. В каждом — классы представления, сервиса и репозитория.
- **More Information**: REQ-MAINT-001, REQ-FUNC-001…005. Решение ADR-0001.

- **ID**: DES-003-безопасность
- **Title**: Локальность и целостность данных
- **Viewpoint**: Информация (2.2.7), Структура (2.2.5)
- **Representation**: Все данные хранятся в файле `utilitysmart.db`. Сетевые сокеты не открываются. Запись в БД выполняется в транзакции; при сбое транзакция откатывается.
- **More Information**: REQ-SEC-001, REQ-REL-001. Решение ADR-0002.

- **ID**: DES-004-данные
- **Title**: Модель данных SQLite
- **Viewpoint**: Информация (2.2.7)
- **Representation**: Таблицы `tariffs`, `readings`, `calculations`. Деньги — `INTEGER` (копейки). Дата — `TEXT` в формате ISO 8601.
- **More Information**: REQ-FUNC-004, REQ-REL-001. Решение ADR-0003.

- **ID**: DES-005-расчёт
- **Title**: Алгоритм расчёта платежа
- **Viewpoint**: Алгоритм (2.2.10)
- **Representation**: Разница показаний умножается на тариф (в копейках). Результат делится на 100 для отображения. Проверка: текущее ≥ предыдущего.
- **More Information**: REQ-FUNC-002, REQ-PERF-001. Решение ADR-0003.

- **ID**: DES-006-интерфейс
- **Title**: Экраны приложения
- **Viewpoint**: Интерфейс (2.2.8)
- **Representation**: Главное окно (ввод показаний, кнопка «Рассчитать», итог), окно тарифов (поля ХВ, ГВ, электро), окно истории (таблица). Макеты — в `docs/sysml/`.
- **More Information**: REQ-INT-001, REQ-INT-002, REQ-FUNC-004.

- **ID**: DES-007-экспорт
- **Title**: Экспорт истории в CSV
- **Viewpoint**: Интерфейс (2.2.8), Алгоритм (2.2.10)
- **Representation**: Формируется файл UTF-8 с заголовком `Дата;Ресурс;Показание;Тариф;Сумма`. Разделитель `;` для совместимости с Excel.
- **More Information**: REQ-FUNC-005, REQ-COMP-001.

- **ID**: DES-008-сборка
- **Title**: Сборка и поставка
- **Viewpoint**: Развёртывание (2.2.14)
- **Representation**: CMake-проект, цель `UtilitySmart`. После сборки создаётся portable-архив с EXE и DLL.
- **More Information**: REQ-INST-001, REQ-BUILD-001. Решение ADR-0005.

## 5. Приложения {#5-appendixes}

### Приложение А. DDL SQLite

```sql
CREATE TABLE tariffs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    resource TEXT NOT NULL CHECK (resource IN ('cold_water','hot_water','electricity')),
    price_cents INTEGER NOT NULL CHECK (price_cents >= 0),
    valid_from TEXT NOT NULL
);

CREATE TABLE readings (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    resource TEXT NOT NULL,
    value INTEGER NOT NULL CHECK (value >= 0),
    taken_at TEXT NOT NULL
);

CREATE TABLE calculations (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    calc_date TEXT NOT NULL,
    resource TEXT NOT NULL,
    prev_value INTEGER NOT NULL,
    curr_value INTEGER NOT NULL,
    tariff_cents INTEGER NOT NULL,
    total_cents INTEGER NOT NULL
);
